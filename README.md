# 模型价格计算 · Model Price Calc

> 一个 Operit ToolPkg 插件：按「中转站」分组管理模型价格，随时查看**这条消息**和**整个对话**花了多少钱。
>
> **纯本地 · 零 token · 不联网 · 不上传**

![Operit](https://img.shields.io/badge/Operit-ToolPkg-blue)
![version](https://img.shields.io/badge/version-0.9.9-green)
![license](https://img.shields.io/badge/license-MIT-yellow)

---

## ✨ 这是什么

Operit 自带统计页只能看总数，也没法按你自己的中转站价格算。这个插件补上了这块：

- 📇 **价格配置页**：自定义中转站 + 模型，分别填「输入 / 缓存读取 / 缓存写入 / 输出」单价（元/百万 token），支持**按次计价**
- 💰 **长按任意消息 →「这条花了多少」**：按该条消息实际 token 用量算钱
- 🧾 **长按任意消息 →「本对话花了多少」**：逐条匹配价格后汇总，还能**按模型分组**看占比
- 🔄 **从软件同步中转站**：一键读取 Operit 本地配置，把中转站和模型全导进来，不用手抄
- 🎯 **自动匹配价格**：按「中转站名 + 模型名」宽松匹配（互为子串也算），对不上就跳过并提示，绝不瞎算

---

## 🔒 隐私与零消耗（设计原则）

这个插件被设计成一个**账本 + 计算器**，只展示聊天本身**已经产生**的费用，不制造账单：

| 项目 | 说明 |
|---|---|
| 是否调用模型 API | ❌ 完全不调用 |
| 是否消耗 token | ❌ 零消耗 |
| 是否联网上传 | ❌ 全程本地 |
| 数据来源 | 本机 SQLite（`app_database`）与 SharedPreferences |
| 计算位置 | 设备端进程内完成 |

> token 用量取自消息对象；请求次数取自本地数据库（按时间窗圈选）。**不向对话注入任何内容。**

## 📦 安装

1. 下载 Releases 里最新的 `模型价格计算-vX.Y.Z.toolpkg`
2. 在 Operit 中导入该 `.toolpkg`（工具包 → 导入）
3. 启用插件，**重启 Operit** 生效
4. 侧边栏会出现「模型价格」入口

> **要求**：Operit **1.12.1+4** 或更高（长按菜单需 `api_version 1.0.1`）。

---

## 🚀 快速上手

1. 点侧边栏 **「模型价格」** 进入配置页
2. 点 **「⟳ 从软件同步中转站（点这里）」**，勾选要同步的中转站 → 一键导入
3. 给常用的模型填上单价（留空 = 0 元）
4. 回到聊天，**长按任意消息** → 选「这条花了多少」或「本对话花了多少」

### 单价字段说明

| 字段 | 含义 | 留空 `""` 的含义 |
|---|---|---|
| 输入 | 未缓存输入单价 | = 0 元 |
| 缓存读取 | 缓存读取单价 | = 0 元 |
| 缓存写入 | 缓存写入单价 | = **按输入单价**；填 `0` = 免费 |
| 输出 | 输出单价 | = 0 元 |
| 按次 | 每次请求单价 | = 不做按次计费（走 token 计费） |

> ⚠️「缓存写入」留空和填 `0` **语义不同**（前者跟输入价，后者免费），注意区分。

---

## 🧮 计费公式

```
未缓存输入 = 总输入 − 缓存读取

费用 = (未缓存输入 × 输入价
      + 缓存读取 × 缓存读取价
      + 缓存写入 × 缓存写入价
      + 输出 × 输出价) / 1,000,000

若「按次单价」> 0 → 改为：费用 = 请求次数 × 按次单价
```

关键点：

- **请求次数**靠「时间窗」在 `token_usage_records` 里圈选：
  `开始 = sentAt`，`结束 = sentAt + waitDurationMs + outputDurationMs + 1000ms`（实测误差仅 1~6 毫秒）
- **单条消息算不出「缓存写入」费用**：因为消息快照只有 `inputTokens / outputTokens / cachedInputTokens` 三个字段，没有 cacheWriteTokens（官方统计页同样算不出，属通病）

## 🎯 自动匹配规则

```
消息 provider："OPENAI_GENERIC/MyProvider"  →  取斜杠后 "MyProvider"
归一化：去所有空白 + 转小写
宽松相等：完全相同  或  互为子串（"abc" ⊂ "abc中转" ✅）

优先「中转站 + 模型」都匹配；退化到「只对模型名」；都失败 → 跳过并计数提示
```

## 🛠 二次开发

源码目录结构即 ToolPkg 结构，可直接改。改完用 Operit 的
`operit_editor:debug_install_toolpkg` 烧录（`source_path` 填仓库根目录），
再重启 Operit 生效。

**重要约束**：

1. 每个 `.ui.js` **必须自包含** —— Operit 的 UI 运行时只认自包含引用，被路由引用的 UI 文件不能 `require` 别的 js，需在自己文件内部重复定义用到的工具函数（这是**故意**的，别"优化"掉）。
2. 长按菜单需 `api_version: "1.0.1"`。
3. `rawQuery` 的参数数组里**每一项都必须是 String**。
4. 无 root 也能读库：走 **进程内** `Java.getApplicationContext().getDatabasePath()`，这是唯一可行路径。

更多细节见 `docs/开发手册.md`。
