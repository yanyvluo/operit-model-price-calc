## 〇、一句话概述

这是一个**纯本地的 Operit ToolPkg 插件**：在侧边栏提供"按分组管理"的价格配置页；在聊天消息长按菜单里加两项——「这条花了多少」「本对话花了多少」。它**读本地 SQLite 数据库**拿 token 用量和请求次数，**按 token 或按次**算钱。

**关键特性**：零 token 消耗（不发任何 API 请求）、能按「中转站名+模型名」自动匹配价格、能从软件配置一键同步中转站、支持三级分类与调序。

## 六、数据存储

SharedPreferences（**三个 UI 文件共用同一份，名字写死一致**）：

```js
var PREFS_NAME = "toolpkg_price_calc";
var DATA_KEY = "price_calc_data_v1";

var ctx = Java.getApplicationContext();
var prefs = ctx.getSharedPreferences(PREFS_NAME, 0);

// 读
var raw = String(prefs.getString(DATA_KEY, ""));
// 写
prefs.edit().putString(DATA_KEY, JSON.stringify(data)).apply();
```

### 数据结构（v0.9.9 —— 含分组）

```json
{
  "groups": ["<分组A>", "<分组B>"],
  "providers": [
    { "id": "p_xxx", "name": "<你的中转站名>", "groupName": "<分组A>",
      "models": [
        { "id": "m_xxx", "name": "<model-name>",
          "input": "x", "cached": "z", "cacheWrite": "", "output": "y", "perRequest": "" }
      ] }
  ],
  "active": { "providerId": "p_xxx", "modelId": "m_xxx" }
}
```

- `groups` 是**字符串数组**（有序，决定显示顺序）。
- `groupName` 为 `""` 表示**未分组**。
- **老数据没有 `groups` / `groupName` 字段 → `sanitize()` 自动补空**，全部进"未分组"，兼容正常。

### 价格语义（**核心约定，别改**）

| 字段 | 含义 | 留空 `""` 的含义 |
|---|---|---|
| `input` | 未缓存输入单价（元/百万token） | = 0 元 |
| `cached` | 缓存读取单价 | = 0 元 |
| `cacheWrite` | 缓存写入单价 | = **按 input 单价**；填 `"0"` = 免费 |
| `output` | 输出单价 | = 0 元 |
| `perRequest` | 按次单价（元/次） | = 不做按次，走 token 计费 |

> 注意 `cacheWrite` 的 `""` 和 `"0"` **语义不同**（前者=跟输入价，后者=免费），所以它有独立的 `asStr()`，**不要**套 `asPrice()` 的"0→空"迁移。

## 八、★ 核心突破 B：读 Operit 软件配置（v0.6.0 新增）

「从软件同步中转站」功能的底层。配置存在 **protobuf 包装的 JSON** 里：

```
路径：ctx.getFilesDir().getAbsolutePath() + "/datastore/model_configs.preferences_pb"
     => /data/user/0/com.ai.assistance.operit/files/datastore/model_configs.preferences_pb
大小：约 45 KB
```

### ⚠️ 唯一可行的读取方式：`Runtime.exec("cat ...")`

**其他方式全部失败**（实测）：`File.$new` / `FileInputStream.$new` / `RandomAccessFile.$new` 都报
`static method '$new' not found`；`Paths.get` + `Files.readAllBytes` / `Files.newInputStream` 抛 `StackOverflowError`；
`ctx.openFileInput(path)` 不认路径分隔符。

```js
var Runtime = Java.use("java.lang.Runtime");
var proc = Runtime.getRuntime().exec("cat " + path);
var is = proc.getInputStream();
var bytes = [];
var b;
while ((b = is.read()) !== -1) { bytes.push(b & 0xFF); }   // 逐字节读
proc.waitFor();
is.close();
```

### 解析四步

1. **手写 UTF-8 解码** `utf8Decode(bytes, start, end)`（宿主没有现成的；处理 1/2/3/4 字节序列，含 `0x80–0xBF` 续字节）。
2. **扫描字节流**找 `config_` 前缀：`0x63 6F 6E 66 69 67 5F`。
3. 跳到 `*`（`0x2A`）后的 `{`（`0x7B`），**大括号配平**提取 JSON（带 `inStr`/`esc` 状态，避免字符串内的括号干扰）。
4. `JSON.parse` 出 `{ name, apiProviderType, modelName, apiEndpoint }`；模型名按 `,` 拆分。

> 首块 `config_list` 要跳过（`id === "list"`），它不是配置项。

### 合并进价格表 `mergeConfigsIntoData(data, configs)`

- **只增不删**：中转站/模型不存在才 push，价格字段**全留空**。
- 同名中转站**不新建**，但**会补它缺的模型**（v0.9.9 起被同步面板利用）。
- 已有的价格**绝不改动**。

## 九、★ 计费公式（扒自官方 `TokenCostCalculator.kt`）

```
未缓存输入 = 总输入 − 缓存读取        (= inputTokens − cachedInputTokens)
费用 = 未缓存输入 × 输入价
     + 缓存读取 × 缓存读取价
     + 缓存写入 × 缓存写入价
     + 输出 × 输出价
     全部 ÷ 1_000_000
```

- 缓存写入价："空"取输入价、"0"=0、有数取该数。
- 若 `perRequest > 0` → 改为 **按次**：`费用 = 请求次数 × perRequest`。
- ⚠️ **单条消息算不出"缓存写入"费用**——因为 `ChatMessageSnapshot` 只有 `inputTokens / outputTokens / cachedInputTokens` 三个字段，**没有 cacheWriteTokens**。官方统计页对单条也算不出，通病。

## 十、★ 请求次数的时间窗算法（实测 100% 精确）

消息里**没有**请求次数字段，靠"时间窗"去 `token_usage_records` 圈：

```
单条：开始 = sentAt
      结束 = sentAt + waitDurationMs + outputDurationMs + 1000ms
      （因为 completedAt ≈ sentAt + waitDurationMs + outputDurationMs，实测误差仅 1~6 毫秒）
      次数 = SELECT COUNT(*) FROM token_usage_records WHERE occurredAtMs>=开始 AND occurredAtMs<=结束

整段对话：对每条消息分别圈一次，然后求和（逐条匹配必须这么做）
```

## 十一、★ 自动匹配逻辑（v0.5.0 起）

**思路：先匹配中转站名，再匹配模型名。**

```js
// "OPENAI_GENERIC/<你的中转站名>" -> "<你的中转站名>"；"ZHIPU" -> "ZHIPU"
function splitProviderName(provider) {
  var s = asStr(provider);
  var i = s.lastIndexOf("/");
  return i >= 0 ? s.substring(i + 1) : s;
}
// 归一化：去所有空白 + 转小写
function normName(s) { return asStr(s).replace(/\s+/g, "").toLowerCase(); }
// 宽松相等：完全相同 or 互为子串（"abc" ⊂ "abc中转" ✅）
function looseEq(a, b) {
  var x = normName(a), y = normName(b);
  if (!x || !y) return false;
  if (x === y) return true;
  return x.indexOf(y) >= 0 || y.indexOf(x) >= 0;
}
// 主匹配：优先「中转站+模型」都中；退化到「只中模型名」
function findPriceForMessage(data, msg) {
  var providers = (data && Array.isArray(data.providers)) ? data.providers : [];
  var msgProv = splitProviderName(msg.provider);
  var msgModel = asStr(msg.modelName);
  var modelOnly = null;
  for (var i = 0; i < providers.length; i += 1) {
    var p = providers[i];
    var provOk = looseEq(p.name, msgProv);
    var models = Array.isArray(p.models) ? p.models : [];
    for (var j = 0; j < models.length; j += 1) {
      var m = models[j];
      if (looseEq(m.name, msgModel)) {
        if (provOk) return { provider: p, model: m, by: "provider+model", strict: true };
        if (!modelOnly) modelOnly = { provider: p, model: m, by: "model", strict: false };
      }
    }
  }
  return modelOnly;  // null = 没匹配到
}
```

**关键事实**：
- 消息的 `provider` 格式是 `OPENAI_GENERIC/你自己的中转站显示名`，**斜杠后就是你在软件里配的名字**。
- 消息的 `modelName` 与数据库统计表的 `model` 字段**天然一致**。
- 统计表的 `provider` 可能只存 `OPENAI_GENERIC`（不代表自定义名），所以**别拿它匹配中转站**。
- 匹配不到时的策略：**跳过 + 计数提示**，不瞎算。

## 十二、同步面板的排序规则（v0.9.9）

点「从软件同步中转站」后：

1. 读配置 → 按名字合并去重 → 得到 `merged`（软件里的全部中转站）。
2. 逐个与插件现有 `providers` 按**名字**比对（`idxProviderByName`）：
   - 插件没有 → 归入 `news`（**新的，排前面**），标 `N 个模型 · 新`
   - 插件已有 → 归入 `existings`（**沉底**），并算出里面有几个模型是插件没有的：
     - 有新的 → `已导入 · 可补 N 个新模型`
     - 无新的 → `已导入 · 无新模型`
3. `all = news.concat(existings)` → `setSyncList(all)`。
4. **默认只勾选 `news`**（避免手滑提交一堆已存在的）。
5. 提交 `doSync()` → `mergeConfigsIntoData`（只增不删，已有价格不动）。

**判断依据是"中转站名"**，所以：
- 手动改过名 → 名字不同 → 会被当成"新的"显示出来。
- 同一中转站在软件里加了新模型 → 因为名字已存在而沉底，但标注会显示"可补 N 个新模型"。

## 十三、★ 平台能力边界（三次实测结论，极其重要）

**Operit 1.12.2 的 Compose DSL 是"静态渲染"，交互只支持离散单击。**

| 想做 | 类型定义里 | 运行时实际 |
|---|---|---|
| 动画（AnimatedVisibility / animateFloat…） | ❌ 完全没有 | ❌ 做不了 |
| `setTimeout` 里 `setState` 触发重渲染 | ✅ 有 setTimeout | ❌ **不触发重渲染** |
| `combinedClickable` / `onLongClick`（长按） | ✅ 声明了 | ❌ **静默失效** |
| `Modifier.dragGestures` / `transformGestures` | ✅ 声明了 | ❌ 长按都触发不了，拖动无从谈起 |
| 普通 `onClick` | ✅ | ✅ **唯一真正可用** |

### 具体踩坑记录

1. **动画尝试（v0.9.0）**：用 `setTimeout` 手动补间做"淡入+上滑"。结果 `runAnim` 里 `setAnimP(0)` 在点击瞬间生效（渲染了一次 15% 透明），**后续帧全部不生效** → 卡片**永久卡在 `alpha=0.15`，整个界面发灰**。教训：**setTimeout 里的 setState 只改数据、不触发重绘**。
2. **`Card` 的 `elevation` 会发灰**：Material3 里 elevation 叠加 surface tint，深色主题下显灰。**别用它做"浮起"效果**。
3. **长按（v0.9.3）**：给 `Row` 挂 `modifier: ctx.Modifier.combinedClickable({onClick, onLongClick}).toJSON()`，编译通过、无任何报错日志，但**长按毫无反应**。
   → 结论：以后凡"长按 XX"需求，**默认换成按钮 / 点按方案**。

### 因此本插件的交互约定

- 展开/收起：**点标题行**（`Row` 的 `onClick`）
- 调序：**「上 / 下」文字按钮**（`TextButton`）
- 改名：**展开后直接显示 `TextField`**（实时 `onValueChange` 保存）
- 选分组：**点「▶ 选择」展开候选**，选完自动收起
- 确认类操作：**弹窗**（`Dialog` + `Button`）
- 视觉层次：靠**字号 / 颜色 / 分割线 / 缩进**，不靠动画和 elevation

## 十五、踩过的坑（血泪清单）

1. **`placeholder` 不显示** → 1.12.2 只在"输入框空且获得焦点"才显示，平时看不见。**提示一律写进 `label`**。
2. **UI 文件不能互相 require** → 每个 `.ui.js` 必须自包含（见 §二）。
3. **`registerChatMessageMenuItem` 需要 `api_version: "1.0.1"`** → 1.0.1 是 Operit 1.12.1+4 起支持的。写成 `1.0.0` 会不识别。
4. **`rawQuery` 参数必须是 String** → 数字要先 `String(...)`，否则可能抛异常。
5. **无 root 访问 `/data/data/com.ai.assistance.operit/` 会被拒** → 但**进程内**用 `Java.getApplicationContext().getDatabasePath()` 可以，这是唯一可行路径。
6. **已删除的中转站，消息仍留在 `messages` 表里** → 这是历史残留，不是当前配置。所以自动匹配必须有"未匹配跳过"兜底。
7. **改完不重启可能没效果** → 保险起见每次让用户重启一次 Operit。
8. **`asPrice()` 迁移** → 把旧数据里 `input/cached/output/perRequest` 的 `"0"` 自动转成 `""`（语义等价，界面更干净）；**`cacheWrite` 不要迁移**。
9. **循环里定义 `var` 变量 + 闭包引用 = 经典坑** → `for (var i…) { var grpName = arr[i]; … onClick: function(){ 用 grpName } }` 中 `grpName` 会被后续迭代覆盖，**所有 onClick 都指向最后一个值**。修复：整个循环体包进 IIFE `(function (grpName) { … })(arr[i])`。
10. **`combinedClickable` / 长按无效** → 见 §十三。
11. **`setTimeout` 里 `setState` 不触发重渲染** → 见 §十三。
12. **`Card` 的 `elevation` 发灰** → 见 §十三。
13. **别在 UI 代码里用 `File` / `FileInputStream` / `Paths` / `Files`** → 全部报错或栈溢出，读文件只能 `Runtime.exec("cat …")`。
