# 模型价格计算 ToolPkg · 开发/复活手册

> 用途：若 Operit 升级导致插件失效，把**本手册 + 源码包**交给 AI，即可快速修好或从零重写。
> 最后更新：v0.5.0（2026-10-12）

---

## 〇、一句话概述

这是一个**纯本地的 Operit ToolPkg 插件**：在侧边栏提供"按中转站分组"的价格配置页；在聊天消息长按菜单里加两项——「这条花了多少」「本对话花了多少」。它**读本地 SQLite 数据库**拿 token 用量和请求次数，**按 token 或按次**算钱。

**关键特性**：零 token 消耗（不发任何 API 请求）、能按「中转站名+模型名」自动匹配价格。

### ⚠️ 铁律：每个文件必须"自包含"

Operit 1.12.2 的 UI 运行时**只认自包含引用**——被 `registerUiRoute` / `dialog.screen` 引用的 `.ui.js`，必须在**自己文件内部**重新定义它用到的所有函数（`getContext`、`getPrefs`、`asStr`、`numOf`、`fmtMoney`…），**不能 `require` 别的 js**。

所以你会看到 `cost_dialog.ui.js` 和 `chat_total_dialog.ui.js` 里重复了一大堆工具函数——**这是故意的，别"优化"掉**。

唯一例外：`main.js` 可以用 `__importDefault(require("./ui/xxx.ui.js"))` 引 UI 文件。

## 四、ToolPkg API 速查（`dist/main.js`）

入口必须导出 `registerToolPkg` 函数。

```js
function registerToolPkg() {
  // ① 注册 UI 路由（页面本体）
  ToolPkg.registerUiRoute({
    id: "price_manager_route",
    route: "toolpkg:com.yezi.price_calc:ui:price_manager",
    runtime: "compose_dsl",
    screen: settings_ui_js_1.default,
    params: {},
    keepAlive: false,
    title: { zh: "模型价格", en: "Model Price" }
  });

  // ② 侧边栏入口
  ToolPkg.registerNavigationEntry({
    id: "price_manager_sidebar",
    route: "toolpkg:com.yezi.price_calc:ui:price_manager",
    surface: "main_sidebar_plugins",
    title: { zh: "模型价格", en: "Model Price" },
    icon: "Calculate",
    order: 151
  });

  // ③ 工具箱兜底入口
  ToolPkg.registerToolboxUiModule({
    id: "price_manager_settings",
    runtime: "compose_dsl",
    screen: settings_ui_js_1.default,
    params: {},
    title: { zh: "模型价格设置", en: "Model Price Settings" }
  });

  // ④ 长按消息菜单（需要 api_version 1.0.1）
  ToolPkg.registerChatMessageMenuItem({
    id: "price_calc_message_cost",
    title: { zh: "这条花了多少", en: "Cost of this message" },
    icon: "Calculate",
    order: 30,
    senders: ["ai", "user"],
    dialog: {
      screen: "dist/ui/cost_dialog.ui.js",   // ← 相对路径字符串，不是函数
      title: { zh: "本条费用", en: "Message Cost" }
    },
    function: onMessageMenuItem                    // ← 返回 state
  });

  ToolPkg.registerChatMessageMenuItem({
    id: "price_calc_chat_total",
    title: { zh: "本对话花了多少", en: "Total cost of this chat" },
    icon: "Calculate",
    order: 31,
    senders: ["ai", "user"],
    dialog: {
      screen: "dist/ui/chat_total_dialog.ui.js",
      title: { zh: "本对话费用", en: "Chat Total Cost" }
    },
    function: onChatTotalMenuItem
  });

  return true;
}
```

**菜单项的 `function` 负责把数据塞进弹窗 state：**

```js
function onMessageMenuItem(event) {
  var payload = (event && event.eventPayload) ? event.eventPayload : {};
  return { dialog: { state: { message: payload.message, chatId: payload.chatId } } };
}
function onChatTotalMenuItem(event) {
  var payload = (event && event.eventPayload) ? event.eventPayload : {};
  return { dialog: { state: { chatId: payload.chatId } } };
}
```

**弹窗页读取 state：** `ctx.useState("message", null)` → 拿到 `{message, chatId}`。

### 数据结构

```json
{
  "providers": [
    { "id": "p_xxx", "name": "基元律动中转",
      "models": [
        { "id": "m_xxx", "name": "deepseek-flash",
          "input": "1", "cached": "0.02", "cacheWrite": "", "output": "4", "perRequest": "" }
      ] }
  ],
  "active": { "providerId": "p_xxx", "modelId": "m_xxx" }
}
```

### 价格语义（**核心约定，别改**）

| 字段 | 含义 | 留空 `""` 的含义 |
|---|---|---|
| `input` | 未缓存输入单价（元/百万token） | = 0 元 |
| `cached` | 缓存读取单价 | = 0 元 |
| `cacheWrite` | 缓存写入单价 | = **按 input 单价**；填 `"0"` = 免费 |
| `output` | 输出单价 | = 0 元 |
| `perRequest` | 按次单价（元/次） | = 不做按次，走 token 计费 |

> 注意 `cacheWrite` 的 `""` 和 `"0"` **语义不同**（前者=跟输入价，后者=免费），所以它有独立的 `asStr()`，**不要**套 `asPrice()` 的"0→空"迁移。

## 八、★ 计费公式（扒自官方 `TokenCostCalculator.kt`）

```
未缓存输入 = 总输入 − 缓存读取        (= inputTokens − cachedInputTokens)
费用 = 未缓存输入 × 输入价
     + 缓存读取 × 缓存读取价
     + 缓存写入 × 缓存写入价
     + 输出 × 输出价
     全部 ÷ 1_000_000
```

- 缓存写入价："空"取输入价、"0"=0、有数取该数。
- 若 `perRequest > 0` → 改为 **按次**：`费用 = 请求次数 × perRequest`。
- ⚠️ **单条消息算不出"缓存写入"费用**——因为 `ChatMessageSnapshot` 只有 `inputTokens / outputTokens / cachedInputTokens` 三个字段，**没有 cacheWriteTokens**。官方统计页对单条也算不出，通病。

---

## 九、★ 请求次数的时间窗算法（实测 100% 精确）

消息里**没有**请求次数字段，靠"时间窗"去 `token_usage_records` 圈：

```
单条：开始 = sentAt
      结束 = sentAt + waitDurationMs + outputDurationMs + 1000ms
      （因为 completedAt ≈ sentAt + waitDurationMs + outputDurationMs，实测误差仅 1~6 毫秒）
      次数 = SELECT COUNT(*) FROM token_usage_records WHERE occurredAtMs>=开始 AND occurredAtMs<=结束

整段对话：对每条消息分别圈一次，然后求和（逐条匹配必须这么做）
```

## 十、★ 自动匹配逻辑（v0.5.0 新增）

**思路：先匹配中转站名，再匹配模型名。**

```js
// "OPENAI_GENERIC/基元律动中转" -> "基元律动中转"；"ZHIPU" -> "ZHIPU"
function splitProviderName(provider) {
  var s = asStr(provider);
  var i = s.lastIndexOf("/");
  return i >= 0 ? s.substring(i + 1) : s;
}
// 归一化：去所有空白 + 转小写
function normName(s) { return asStr(s).replace(/\s+/g, "").toLowerCase(); }
// 宽松相等：完全相同 or 互为子串（"基元律动" ⊂ "基元律动中转" ✅）
function looseEq(a, b) {
  var x = normName(a), y = normName(b);
  if (!x || !y) return false;
  if (x === y) return true;
  return x.indexOf(y) >= 0 || y.indexOf(x) >= 0;
}
// 主匹配：优先「中转站+模型」都中；退化到「只中模型名」
function findPriceForMessage(data, msg) {
  var providers = (data && Array.isArray(data.providers)) ? data.providers : [];
  var msgProv = splitProviderName(msg.provider);
  var msgModel = asStr(msg.modelName);
  var modelOnly = null;
  for (var i = 0; i < providers.length; i += 1) {
    var p = providers[i];
    var provOk = looseEq(p.name, msgProv);
    var models = Array.isArray(p.models) ? p.models : [];
    for (var j = 0; j < models.length; j += 1) {
      var m = models[j];
      if (looseEq(m.name, msgModel)) {
        if (provOk) return { provider: p, model: m, by: "provider+model", strict: true };
        if (!modelOnly) modelOnly = { provider: p, model: m, by: "model", strict: false };
      }
    }
  }
  return modelOnly;  // null = 没匹配到
}
```

**关键事实**：
- 消息的 `provider` 格式是 `OPENAI_GENERIC/你自己的中转站显示名`，**斜杠后就是你在软件里配的名字**。
- 消息的 `modelName` 与数据库统计表的 `model` 字段**天然一致**。
- 统计表的 `provider` 可能只存 `OPENAI_GENERIC`（不代表自定义名），所以**别拿它匹配中转站**。
- 匹配不到时的策略：**跳过 + 计数提示**，不瞎算。

## 十二、踩过的坑（血泪清单）

1. **`placeholder` 不显示** → 1.12.2 只在"输入框空且获得焦点"才显示，平时看不见。**提示一律写进 `label`**。
2. **UI 文件不能互相 require** → 每个 `.ui.js` 必须自包含（见 §二）。
3. **`registerChatMessageMenuItem` 需要 `api_version: "1.0.1"`** → 1.0.1 是 Operit 1.12.1+4 起支持的。写成 `1.0.0` 会不识别。
4. **`rawQuery` 参数必须是 String** → 数字要先 `String(...)`，否则可能抛异常。
5. **无 root 访问 `/data/data/com.ai.assistance.operit/` 会被拒** → 但**进程内**用 `Java.getApplicationContext().getDatabasePath()` 可以，这是唯一可行路径。
6. **已删除的中转站，消息仍留在 `messages` 表里** → 这是历史残留，不是当前配置。所以自动匹配必须有"未匹配跳过"兜底。
7. **改完不重启可能没效果** → 保险起见每次让用户重启一次 Operit。
8. **`asPrice()` 迁移** → 把旧数据里 `input/cached/output` 的 `"0"` 自动转成 `""`（语义等价，界面更干净）；**`cacheWrite` 不要迁移**。
9. **旧版 FlClash 不认 Vless+Reality** → 与本插件无关，但同环境易混淆（需 FlClash v0.8.98+）。
